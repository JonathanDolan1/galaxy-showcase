02 / How it works

How I keep it running

Igor is an always-on agent that builds my morning brief, takes voice notes and queues coding jobs. Around it, I built a board that tracks open work like a support queue and a watcher that checks whether jobs produced fresh results.

One machine stays on
An old laptop runs Linux around the clock. Some scheduled jobs still need my dev laptop, so I’m moving them to the always-on server.
Check the output
The watcher looks for fresh results and alerts me when a job’s output goes stale.
Start with the logs
AI can search the logs; the only actions it can take are sending me one alert and logging a job check-in.
Follow the voice request
A Siri phrase can send a request from my phone to the server to switch the lights.
Keep public data small
This map uses a small allowlist of public descriptions and connections. I update it as a dated snapshot.

03 / Lessons

What I learned

  1. Watch the output, not just the process.

    A scheduled job once skipped three days without anyone noticing, so I built a watcher that checks every job actually produced fresh results.

  2. Scheduled jobs need a machine that stays awake.

    Jobs on my laptop missed runs while it slept, so I’m moving them to the always-on server.

  3. Allowlist, not blocklist.

    For anything public, I list what’s allowed out instead of trying to list every secret to hide.

  4. Rules work better as code.

    I’m moving “never read secret files” from a line in a prompt into a script that blocks the action.

  5. Write it down for the next person.

    Handoff notes let one AI tool, or me a week later, pick up where the last one stopped.
